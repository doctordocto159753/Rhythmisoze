# Rhythmisoze — ریتمیسوز

**Turn your voice into an instrument** · **صدات رو به ساز تبدیل کن**

Hum, sing or beatbox a musical idea. Rhythmisoze transcribes it, tidies it into
something musically usable, plays it back on an instrument, and gives you a WAV
and a MIDI file — all of it in your browser, with nothing uploaded until you
choose to publish.

The product's value is not raw audio-to-MIDI. It is the **retouch layer** that
closes the gap between an imperfect vocal gesture and material that feels
intentional: octave-error removal, quantization, key detection, scale snapping
and note cleanup, behind a single Raw→Clean control.

---

## Quick start

```bash
npm ci
npm run dev          # http://localhost:3000 → redirects to /fa or /en
```

No environment variables are needed. The entire creation flow — record,
transcribe, retouch, choose an instrument, render, download — works with an
empty `.env`. Publishing is the only part that needs configuration; see
`docs/runbooks/deployment.md`.

```bash
npm run verify       # typecheck + lint + 389 unit tests
npm run build        # production build
npm run test:e2e     # browser matrix (run `npx playwright install` once first)
```

## The pipeline

```
microphone ─► MonoAudio ─► transcriber ─► NoteEvent[] ─► refine() ─► synth ─► WAV
                (mono float PCM)   │                       │            │
                                   │                       │            └─ OfflineAudioContext
                                   │                       └─ pure, deterministic, 181 parity tests
                                   └─ Basic Pitch in a worker, YIN as fallback
```

Rhythm is a separate path, not melody with the pitch discarded:

```
microphone ─► MonoAudio ─► spectral-flux onsets ─► kick/snare/hat ─► GM drums
```

## Five things worth knowing before changing anything

1. **`src/packages/retouch/port.ts` is a port, not an implementation.** It
   mirrors `reference/humtool.py` function by function, down to Python's
   round-half-to-even and its modulo sign. `tests/unit/retouch-golden.test.ts`
   checks 181 assertions against fixtures generated by running the real Python.
   Improvements belong in `extensions.ts`, never in `port.ts`.

2. **Tempo comes from the user, always.** Tap tempo plus a metronome is a
   product constraint, not a convenience (PRD R-02/R-03). `estimateTempo` exists
   only to report what the app *heard*, so a user whose tap was half-time can see
   the discrepancy. It never drives the grid.

3. **Time runs left-to-right in both locales.** Text direction flips for
   Persian; the waveform, the piano roll, the cleanup slider and the playhead do
   not. Everything else uses logical CSS properties.

4. **Nothing is uploaded until Publish.** There is no code path that sends
   unpublished audio anywhere. The landing page says so, and the architecture is
   what makes it true rather than a policy.

5. **One state machine.** `src/features/state/machine.ts` is a transition table,
   not a set of booleans. An invalid transition is a lookup miss, and 26 tests
   assert the whole reachability graph.

## Known gaps

Stated here rather than left to be discovered. The full list with detail is in
`docs/product-decisions.md`.

- **The architecture quality gate has not been run** (ADR-001). No audio corpus
  existed to run it against, so Basic Pitch's accuracy and speed on real devices
  are unverified. The built-in pitch tracker exists as a working fallback.
- **Recorded instruments still need a human listening panel** (ADR-002). Six
  licensed multisample packs now ship and the technical loading/rendering gates
  pass, but the documented subjective >=4/5 score has not been claimed without
  listeners.
- **No real-device testing has been performed** (US-1203). The checklist is in
  `docs/runbooks/manual-device-checks.md`.
- **No privacy policy or error monitoring** (Q-F2, Q-G3, both unanswered).
